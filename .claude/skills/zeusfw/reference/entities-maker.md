# Entities, maker.php, feeders, update.sh

## Entity YAML (`web/classes/yaml/<table>.yaml`; framework tables in `core/classes/yaml/`)

```yaml
table:
  name: clinics
  class: clinicsClass                 # generated class name
  # extention: __FWDIR__ . '/xClassEx.php'   # (sic) optional: generated class require_once's this file
  fields:
    - name: guid
      type: "@guid"                   # CHAR(36) NOT NULL
    - name: cdate
      type: "@cdate"                  # DATETIME DEFAULT CURRENT_TIMESTAMP
    - name: cuser
      type: "@cuser"                  # CHAR(32) NOT NULL
    - name: deleted
      type: "@delete"                 # DATETIME DEFAULT NULL (soft delete)
    - name: data
      type: "@json"                   # JSON NOT NULL DEFAULT json_array()
    - name: clinic_name
      type: varchar(128)
      required: true                  # NOT NULL
      default: null                   # DEFAULT NULL; any other value -> DEFAULT <value>
    - name: active
      type: tinyint(1)                # = boolean; also `type: boolean`
      default: 1
    - name: username
      type: varchar(64) UNIQUE        # constraints live in type:, never hand-added to the .sql
    - name: updated
      type: datetime
      on_update: CURRENT_TIMESTAMP
```

- `id INTEGER NOT NULL AUTO_INCREMENT UNIQUE` is added automatically. Charset utf8mb4, collation
  `utf8mb4_unicode_ci`, engine InnoDB unless `table: charset/collate/engine` say otherwise.
- No foreign keys anywhere in the framework; referential integrity is in app code.
- A YAML comment on each non-obvious field is the house style.

### Webform part of the same YAML

```yaml
form:
  name: clinics
  method: post
  action: "#"
  inputs:
    - name: clinic_name
      label: "Όνομα κλινικής"
      type: text                      # text, hidden, checkbox, select, textarea, ...
    - name: row_guid                  # carries an existing row's guid -> storeFormResults() updates instead of inserts
      type: hidden
form_view:                            # every form needs a view with buttons:, or it renders without buttons
  default: view_full
  view_full:
    buttons:
      - { type: submit, label: "Αποθήκευση" }
      - { type: button, label: "Άκυρο", action: "window.location.href='index.php';" }
    fields: [ { name: clinic_name }, { name: row_guid } ]
table_view:                           # results table (renderFormResults)
  default: table_default
  table_default: [ { name: clinic_name } ]
  actions_label: "Ενέργειες"
  buttons:
    - { type: edit, handler: clinics_edit_url }
    - { type: delete, handler: clinics_delete_url }
```

Forms are stored in the DB: after changing `form:`/`form_view:` run `maker.php form:load yaml/<form>.yaml`
(update.sh's "forms" step). Render: `formsClass::renderForm('clinics', $view = null, $default_values)`; results
table: `formsClass::renderFormResults('clinics', $filter, $view)`; POST handling: `formsClass::processform($params)`
/ `storeFormResults($form, $results)`. Checkboxes submit `1`; an unchecked box submits nothing (update leaves the
column alone).

## Generated class API (`web/classes/<table>.php`)

```php
$c = new clinicsClass(['clinic_name' => 'X']);   // or loadFields($array)
$c->setclinic_name('Y'); $c->getclinic_name();  // get<field>/set<field>, field name verbatim
$c->insert(); $c->update(); $c->delete();
clinicsClass::sgetById(5);
clinicsClass::sgetAll($whereClause = null, $limit = null);
clinicsClass::sgetAllFilter('clinics', ['guid' => $g], $sorts = [], $conditionals = []);
clinicsClass::squery()->whereEq('deleted', null)->whereLike('clinic_name', 'A%')
    ->orderBy('clinic_name')->limit(20)->get();  // ->cget() returns class instances; ->toSql() to debug
clinicsClass::sgetConnection();                   // the PDO, for hand-written SQL (always prepared statements)
```

Hand-written methods go in `<table>ClassEx` (app: `web/ClassesEx.php` or its own file; core: `core/<x>ClassEx.php`
wired via `extention:`). `bootstrap_classes.php` (generated by `update:bootstrap`) requires every class.

## maker.php

Run from the directory holding `yaml/` and `sql/`: `web/classes` for the app (`php ../core/maker/maker.php ...`),
or pass `--app-dir=<app root>` (framework tables). `maker.php help` lists everything. Main commands:

| Command | Does |
|---|---|
| `spill:sql[:all]` / `spill:class[:all]` | YAML -> `sql/<t>.sql` / `<t>.php` |
| `update:bootstrap` | rewrite `bootstrap_classes.php` |
| `diff:sql[:all]` | compare YAML with the live table, print `ALTER TABLE` |
| `tables:new:fw|web` | tables in YAML but not in the DB |
| `feed:gen:yaml`, `feed:load`, `feed:clean`, `feed:info`, `feed:sync:fields`, `feed:hashes:clean` | feeders (run in `web/content`, `--name=<feeder>.feeder.yaml`) |
| `form:load`, `form:view`, `gen:form:array|html|all` | webforms |
| `rbac:{users,roles,permissions,role-permissions,user-roles}:{list,add,edit,remove}` | RBAC admin (`--yes` to remove) |
| `data:export`, `msg:new <user> <message>` | misc |

`diff:sql` normalises before comparing: `int(11)` = `int`, `tinyint(1)`/`bool` = `boolean`, whitespace runs,
`UNIQUE` compared via the index (`Key` = UNI/PRI). If it still reports a column on every run, the comparison is
what's wrong (see `core/maker/functions.php` `syncTableWithYAML()`), not the database.

Feeders: see zeusfw `docs/feeders-yaml.md`. A generated item's `schema:` is relative to `web/content`
(`../classes/yaml/<t>.yaml`); `feed:load` is idempotent (hashes in `feed_hashes`).

## fw/bin/update.sh (from the app root)

Steps: core tables (spill + import missing) -> core diff -> app tables -> app diff -> content (feeders:
clean/gen/load) -> forms -> `bin/post-update.sh` if executable -> clear `web/cache/*`.

Options: `--core-tables= --web-tables= --core-diff= --web-diff= --content= --generate-feeders= --clean-feeds=
--forms=` (`ask|yes|all|no`), `--yes` (yes to all except the diffs and clean-feeds), `--non-interactive`
(unanswered = no), `--dry-run` (writes nothing, prints missing tables and diffs), `--help`. Exits 1 on a failed step.

## fw/bin/init.sh

Creates the DB + user (`admin.sql`) and `config/db.php` from prompts; safe to re-run (Enter keeps the shown
value). Passwords with `/ & \` are handled; a `'` in a saved password is truncated on re-read.
